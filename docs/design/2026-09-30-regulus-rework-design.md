# Regulus rework — DESIGN SPEC (2026-09-30)

Статус: дизайн, не реализация. Цифры — рабочая гипотеза «S+ тир, но убиваемый»;
финальный тюнинг после in-game прогонов. Все значения в тиках (20t = 1с).
**Тайминги анимаций — канон**: события/длительности берутся из
`Regulus_EMF_Authoring.json`/`HANDOFF.md` (§8) и опережают любые догадки кода;
механика ждёт authored event-времён, а не наоборот. EMF — зависимость мода
(решение заказчика); её плеер-риг и рантайм реализуются отдельной задачей,
эта спека их только потребляет.

## 0. Что есть сейчас (краткая сверка с кодом)

- Абилки: `lion_heart`, `mania_of_greed`, `greeds_embrace`, `lion_roar`, `counter_strike`
  (скрыта до безумия). `hero/regulus/`, клиент `client/hero/regulus/`.
- Пассивы уже жирные: +70 armor (resolved-кап 30), 100% knockback resist, перма
  Regen I / Speed II / Strength II / Jump II / FireRes, анти-фолл, суперпрыжок.
- Два скрытых ревайва: `RegulusTotemController` (1/сессию героя, фулл-хил) и
  `RegulusBonusLife` (1 за безумие, 50% хп). В сумме Regulus имеет ~3 жизни.
- Evangelion — плоский item-спрайт (`models/item/evangelion.json`), ПКМ → 10с чтения
  с полной неуязвимостью → вечное безумие до смерти/снятия героя.
- VFX: только ванильные партиклы + костыль фейковых `LightningBolt`-энтити в клетке.
  Veil у регулуса нет вообще.
- `RegulusGameTests` (~660 строк) — characterization-пины текущего поведения;
  почти все переписываются.

## 1. Новая механика: сердца («маленький король»)

Канон: Регулус хранит своё сердце в «жёнах». У нас — в живых существах рядом.

### Правила

- **Кто получает**: `LivingEntity` с `EntityType` из namespace `minecraft`,
  в радиусе 20 блоков, не игрок, **не враждебная** (`Enemy` исключены —
  сердце живёт в мирных/нейтральных носителях; решение заказчика
  2026-09-30), не уже отмечена. Кастомные сущности
  (призванная Рем, боссы мода) исключены по namespace + дата-тегом
  `superheroes:heartless` (data-driven запрет для особых ванильных типов —
  напр. боссы `wither`/`warden`/`ender_dragon` вносятся в тег сразу,
  `armor_stand` тоже).
- **Метка**: attachment на сущность `REGULUS_HEART_OWNER` (UUID владельца).
  Одна сущность = максимум одно сердце одного Регулуса (первый взявший).
- **Сбор**: аура проверяет радиус раз в 20t через `ctx.ticks().player`.
  Метка бесплатна и мгновенна — «сердце просто оказывается внутри».
- **Кап**: 12 сердец.
- **Смерть носителя**: сердце сгорает + откат владельцу — 10% макс-хп
  true damage (свой damage type `regulus_heart_backlash`, не резистится) +
  Weakness I 60t. Сообщение в actionbar.
- **Выгрузка/деспавн носителя**: сердце теряется тихо, без отката
  (выгруженные чанки всё равно не считаются — см. подсчёт).
- **Подсчёт живых сердец**: owner-side `OwnedSessionMap<UUID, Set<UUID>>`;
  сущность-метка — источник истины, сет владельца — кэш для скорости.
  Выгруженная сущность не считается (сердце «спит» — канонно время там стоит).
- **Подсветка только для владельца**: S2C payload `HeartsSyncS2CPayload`
  (список entity-id) → клиент рисует outline/aura через рендер-слой
  только если локальный игрок — владелец. Никакого ванильного glowing.

### Что даёт каждое сердце

| Эффект | За сердце | Кап (12 шт) |
| --- | --- | --- |
| Окно Lion's Heart | +40t | база 60t + 480t = 27с |
| Урон атак/абилок | +2% (мультипликативно на модификатор) | +24% |
| Реген энергии | +0.15/тик | +1.8/тик (база 2 → ~3.8) |

Без сердец Regulus заметно слабее: lion heart держится 3с, урон базовый,
энергия течёт медленно. Это и есть «без сердец он крайне слабый».

## 2. Lion's Heart — реворк («остановленное сердце», ощущение пустоты Годжо)

Заменяет `LionHeartAbility` по сути, id `lion_heart` сохраняется.

- **Toggle**; каст-анимация `lion_heart_activation` (1.60с): защита включается
  на authored event **0.70с** (frame 42 @60fps) — до этой точки урон проходит.
  Ранняя отмена каста (новый урон/действие) до 0.70с = абилка не включилась;
  после — сердце живёт. Blend-out 0.16с, interrupt-safe точка 1.08с.
  Drain 10/тик начинается с момента включения защиты.
- Пока активно: весь урон по Регулусу = 0 (как сейчас), НО
  - **прожектайлы в радиусе 4 блоков останавливаются в воздухе** —
    стрелы/трезубцы/фаерболы/лучи-энтити виснут и падают на землю при
    выключении сердца или смерти носителя-абилки. Реализация: per-tick скан
    `Projectile`/`AbstractHurtingProjectile` в радиусе → обнуление velocity +
    `NO_GRAVITY` lock (`EntityControlLock`/`ControlLockKind` уже есть) +
    клиентский «застывший» тинт.
  - голод не тратится, knockback уже нулевой пассивом — атаки «доходят
    до бесконечности и не приходят никогда».
- **Окно безопасности**: 60t + 40t×сердца (кап 27с). Внутри окна — бесплатное
  бессмертие.
- **Перегрев** (держишь дольше окна): урон 1.5хп/с, растёт +0.5хп/с каждые 40t;
  принудительное выключение при хп ≤ 4.0 + кулдаун 600t после принудительного.
  Визуал перегрева: дрожь контура + треск (существующий `CracksOverlayHud`
  перекрашивается в «время трещит»).
- **Активация больше не делает** `removeAllEffects()` — чистит только
  негативные эффекты (не стрипает баффы/пассивы).
- **При выключении**: «возврат времени» — все остановленные прожектайлы
  падают, небольшой импульс (как сейчас, push 1.5).

## 3. Lion's Roar → «дробь» (реворк в разрушительный залп)

id `lion_roar` сохраняется (persisted id), имя/описание/lang переписываются:
«Пинок бездны» / дробь камней. Клип **`debris_kick`** (2.20с, once):
замах назад→вперёд ногой с привязкой бедра к тазу; authored events
`sweep` **0.55с** и `impact` **0.70с**; blends 0.11с/0.17с, interrupt-safe 1.60с.

- **Windup 0–0.70с**: из-под земли перед Регулусом поднимается веер обломков
  (Veil debris + поднятые block-эффекты), игрок замедлен (Slowness I на каст);
  прерывание до 0.70с отменяет залп без кулдауна.
- **Release = `impact` 0.70с**: hitscan-веер, **9 лучей в конусе 35°**,
  дальность 16, каждый 7 урона (`regulus_debris` damage type,
  bypasses_cooldown) + отброс; одновременно мировой звук удара.
- **Recovery** до конца клипа (2.20с); interrupt-safe точка 1.60с; дальше
  blend в `combat_idle`.
- **Лом блоков**: каждый луч пробивает до 3-х ломаемых блоков через
  `WorldDestructionPolicy.tryBreak` (гейты тега/claim/mobGriefing уже внутри);
  лучшее приближение к «разрушительной дроби» без самопального грифинга.
- Стоимость 250, кулдаун 400t (20с). Звук: низкий рык + хруст камня (OGG).

## 4. Баланс

### 4.1 Mania of Greed (`mania_of_greed`)

Сейчас: притягивание + при отпуске 10с полный лок цели + 100% входящего урона
в очередь одной кучей + бесплатный стероид кастеру. = гарант-убийство игрока.

Новое:
- Магнит: pull 0.6/тик, дальность 100/110, drain 5→8/тик — канал ограничен
  ~6с эффективного времени. **Каст играет `mania_of_greed_cast` (2.10с):
  захват цели включается на authored event 0.94с** — до него цель не
  выбрана, прерывание каста = магнит не стартовал (без кулдауна);
  interrupt-safe точка 1.42с. Во время канала кастер под Slowness/Jump
  debuff как сейчас.
- **Фриз при отпуске**: 80t (4с) против игроков, 200t против мобов;
  входящий урон в очередь копится, но при релизе применяется с капом
  **40% макс-хп цели (игроки) / 60% (мобы)**, сумма не выше капа.
- Фриз на выходе стоит **150 энергии** — если её нет, жертва просто
  отпускается без лока (нет бесплатного стана за 0 маны).
- **Стероид кастеру удалён целиком** (было: Resist V + Speed III + Str II +
  +2 knockback на 10с — бесплатная награда за отжатие кнопки).
- Slowness-заморозка кастера во время канала остаётся (цена за стан-лочение).
- **Баг**: `FREEZES` индексирован UUID жертвы → второй Регулус перезаписывает
  state первого, а `EntityControlLock`-owner первого висит навечно.
  Фикс: фриз на уже замороженную цель отказывает («уже во власти жадности»)
  или ключится парой caster+victim. Спека выбирает: **отказ** — проще и
  читаемо для игрока.

### 4.2 Greed's Embrace (`greeds_embrace`) → «стазис-поле»

Сейчас баги: бьёт ВСЕХ живых без `TargetFilters` (союзники, петы, коровы),
лендинг-урон `fellOutOfWorld` ×20%maxHP (ваншот вардена), «клетка» чисто
визуальная из фейковых молний-энтити, трекер ловит случайные фоллы 30с.

Новое — канонная «остановка времени области»:
- Каст `greeds_embrace_cast` (2.20с): acquire-фаза до **0.66с** (прицеливание
  точки до 40 блоков), купол срабатывает на authored event **0.90с**,
  рука опускается на **1.62с** (interrupt-safe). **Стазис-купол радиус 8**,
  длительность 80t.
- Внутри купола: `LivingEntity` через `TargetFilters.hostileTo` (союзники и
  петы НЕ ловятся — фикс friendly-fire) получают стоп-режим:
  `EntityControlLock` NO_AI + NO_GRAVITY + velocity=0, входящий урон копится
  в очередь.
- При закрытии купола (или гибели/деспавне) накопленный урон применяется
  с капом **35% макс-хп цели** + импульс от центра (отброс).
- Стоимость 400, кулдаун 700t (35с). Купол один на кастера.
- Визуал: Veil-кольцо + «остановленные» частицы внутри; НИКАКИХ молний-энтити —
  `spawnFrozenLightning` и `GreedCageController` удаляются, стазис ложится на
  новый `GreedStasisController` (переиспользует очередь урона из greed-механики).

### 4.3 Counter Strike (`counter_strike`)

Сейчас: триггерится не от удара, а от «ближайший хостайл в 120 блоках»
(плюс `getLastHurtByMob` без лимита давности). Урон 30+27+взрыв+похороны
на 20 блоков.

Новое:
- **Цель — только реальный обидчик**: last damager за последние 240t (12с)
  И в радиусе 40 блоков. Фолбэки `getLastHurtByMob`/ближайший хостайл
  удаляются — без обидчика кнопка молчит с подсказкой.
- **Анимация**: клип `counter_attack` (0.90с, impact @0.32с) играет на бите
  ARRIVE→SLAM (телепорт за спину + удар); LIFT жертвы идёт параллельно.
  Тайминг последовательности подгоняется: ударный контакт SLAM совпадает
  с 0.32с клипа (лифт ~20t + пауза ~10t до запуска клипа).
- Урон: лифт-слэм суммарно **15 флэт + 15% макс-хп цели, кап 45**.
  Взрыв остаётся визуальным (`ExplosionInteraction.NONE`), кратер
  `carveCrater` глубина 20→8, радиус 4→3 — зрелищно, но не бункер в бедрок.
- `EnergyLocks` 15с→8с. Кулдаун 600t→800t (40с). `DODGE_COOLDOWN`-карта
  мёртвая — удаляется.
- `stripFlight` атакующего остаётся (канонный «сдернул с небес»).

## 5. Evangelion — активация, плата, смертоносность

Проблемы сейчас: 10с неуязвимый афк-канал → вечное безумие, нулевая цена,
бонус-лайф даром, убить нельзя.

### 5.1 Активация (новая)

- Предмет остаётся (книга — канон), но получает **3D-модель** (Blockbench,
  `geo/item/evangelion.geo.json` + анимация раскрытия; см. §8).
- Зажатие ПКМ = **ритуал по клипу `evangelium_activation` (3.40с)**:
  начало на 0.32с, главный визуальный всплеск на **1.66с**, трансформация
  завершается на **3.00с**, последние 0.40с — settling. Книга на время ритуала
  кружит вокруг игрока (клиентский prop-слой, не entity). Серверный канал:
  **60t до `madness=true`**, settle-окно чисто визуальное.
- Канал **прерываемый**: любой входящий урон ≥ 4хп сбивает ритуал →
  кулдаун предмета 400t. Во время ритуала Регулус **не неуязвим**
  (только Slowness II). Отпускание ПКМ раньше 60t — тоже обрыв.
- Отдельный C2S не нужен: vanilla item-use channel. **Техническая опора:**
  текущий `EvangelionItem.use` не вызывает `player.startUsingItem(hand)` —
  без него `releaseUsing`/`onUseTick` не придут; use должен возвращать
  consume + запускать канал (`getUseDuration` ≥ 60t, `UseAnim` кастомный/BOOK).

### 5.2 Безумие (оплаченное)

- Длительность **900t (45с)** фиксированно, не вечно. Сердца на неё
  НЕ влияют (решение заказчика).
- Баффы как сейчас (+10 armor, +20% макс-хп, +0.4 atk, speed/str/jump amp2,
  regen, resist amp0) — плюс **цена крови**: 0.6 хп/с true-drain всю
  длительность (~27хп за полный режим; перма-regen компенсирует ~40%).
  Пока безумие активно — idle-стойка `evangelium_active_idle` (loop);
  на завершении играет `evangelium_deactivation` (2.00с, state end @0.96с).
- Смерть во время безумия: `RegulusBonusLife` остаётся (одно воскрешение
  50% хп → безумие продолжается), но лишь **один** раз за режим; второй
  летальный удар убивает по-настоящему. Пассивный тотем (1/сессию)
  не трогаем — отдельная механика.
- Режим обрывается досрочно только смертью/снятием героя — «пути назад нет»
  остаётся частью фантазии.

### 5.3 Мультиплеерный баг (симптом подтверждён заказчиком)

Симптом: у НЕ-хоста при активации евангелия нет чёрных полос/зума/эффектов —
только серверные 60t ритуала.

Причина по коду (наиболее вероятная): вся экранная сторона ездит на ручных
S2C-пейлоадах `madness_sync`/`madness_visual` → `ClientMadnessState`.
Удалённый клиент по какой-то причине пакет не применяет (регистрация типа,
тайминг, версия — точную причину покажет живой репро с логом приёма).

**Фикс в спеке (устойчивый, независимо от корня)**:
- `RegulusMadnessState` становится **synced attachment**
  (`AttachmentRegistrar` с `syncWith`) — клиент читает состояние из
  attachment локального игрока, ручной payload для state удаляется.
- `madness_visual` (enter/exit события) либо остаётся как event-payload,
  либо клиент дёргает `BloodRain` по фронту флага `madness` из attachment —
  спека выбирает фронт: меньше сетевого кода, невозможно «потерять» событие
  позже тика.
- Регресс-тест: gametest проверяет что sync-attachment выставлен и
  читается; ручной чек — LAN-двойка (хост + второй игрок) в runtime-чеклисте.

Попутные найденные дефекты (фиксятся в том же пакете):
- `RegulusBonusLife` persistent-attachment не очищается `clearMadness`
  (флаг переживает снятие героя).
- `RegulusMadnessState.bonusLifeAvailable` — мёртвое дублирующее поле.
- Клиентский тайминг на wall-clock заменяется дедлайнами из синка
  (рассинхрон при лагах/паузе).

## 6. Кровь на экране и общий визуал

### Кровь (переделка)

Сейчас `BloodRainHud` рисует `GuiGraphics.fill`-прямоугольники — «пиксельные
сопли». Новое:
- Текстурный оверлей: `textures/gui/regulus/blood_*.png` — 4–6 спрайтов
  потёков по краям экрана, угловые виньетки, один центральный «удар»
  в момент входа в безумие. Альфа-рампа вместо мгновенного затемнения.
- Пульсация альфы под heartbeat (существующий таймер в `MadnessHudOverlay`
  переиспользуется как драйвер).
- `BloodRainHud` переписывается на спрайты; `fill`-капли удаляются.
- **Контент-риск**: `MadnessHudOverlay.FLOATING_SYMBOLS` содержит "卐" —
  удаляется в этом же пакете (риск модерации CurseForge/Modrinth/серверов).

### Veil-эффекты (весь герой)

Всё FX за `client/hero/regulus/fx/veil/` + `FabricLoader.isModLoaded("veil")`,
fallback — минимальные ванильные партиклы. Никаких `veil.*` в `src/main`.

| Механика | Эффект |
| --- | --- |
| Lion's Heart активен | купол дисторшна вокруг игрока, «застывшие» мо́ты в радиусе; прожектайлы получают белый стоп-тинт |
| Сердца | слабый золотой пульс над отмеченными мобами (рендер только владельцу) |
| Перегрев сердца | трещины по контуру игрока + белый шум |
| Магнит жадности | золотая нить к цели + слабое искажение вокруг жертвы |
| Стазис-купол | кольцо на земле, внутри — замедленные/подвешенные частицы, стеклянный купол-шейдер |
| Дробь (roar) | подъём обломков → пыльный конус удара, осколки блоков |
| Контратака | белый флэш при лифте, speed-lines при слэме |
| Ритуал/безумие | парящая книга с золотым свечением, руны-глtч заменяют ANGRY_VILLAGER/LAVA-суп; кровь — спрайты выше |
| Приземление | существующий шоквейв остаётся + слой искажения |

Правило приёмки: каждый эффект сверяется скриншотом в игре (Veil-рендер
≠ ванильные частицы), а не «поставил и пошёл».

## 7. Клиент/сервер заметки

- `HeartsSyncS2CPayload` (entity ids) — новый; `madness_sync` удаляется

## 8. Анимации (master `Regulus_All_Animations.bbmodel`, EMF)

Источник: `D:/WorkFlow/BlockBench 3d models/workbench/regulus_emf_animation_pack/source/Regulus_All_Animations.bbmodel`;
authoring: `export/Regulus_EMF_Authoring.json` (+ `emf_lab` внутри .bbmodel);
handoff: `3d models vault/10 Analysis/regulus_emf_animation_pack/HANDOFF.md`.
EMF — объявляется зависимостью мода (`depends`, hard — решение заказчика);
мод становится **client-only** (`environment: "client"`, dedicated-server
совместимость снята осознанно; `servernoveil`/`runServer` инфраструктура
удаляется). Плеер-риг с extra
shoulder/forearm/hand/shin/foot bones + `mouth_open` и EMF-рантайм реализуются
отдельной задачей — эта спека потребляет её выход и не задаёт её формат.

Клипы (prefix `animation.regulus.`; секунды от начала клипа — канон, 10 штук):

| Клип | Длит. | Loop | События | Механическая привязка |
| --- | --- | --- | --- | --- |
| combat_idle | 4.00с | loop | — | базовая стойка вне безумия |
| lion_heart_activation | 1.60с | once | trigger 0.70с | защита включается на 0.70с |
| debris_kick | 2.20с | once | sweep 0.55с, impact 0.70с | дробь выстреливает на 0.70с |
| lion_roar | 2.60с | once | start 0.82с, peak 0.98с, end 1.62с | резерв: отдельный «рык»-эффект, если понадобится |
| mania_of_greed_cast | 2.10с | once | effect 0.94с | магнит включается на 0.94с |
| greeds_embrace_cast | 2.20с | once | acquire 0.66с, effect 0.90с, release 1.62с | купол на 0.90с |
| counter_attack | 0.90с | once | impact 0.32с | бит ARRIVE→SLAM (§4.3) |
| evangelium_activation | 3.40с | once | begin 0.32с, major 1.66с, complete 3.00с | ритуал, madness на 3.00с (60t) |
| evangelium_active_idle | 4.00с | loop | — | idle во время безумия |
| evangelium_deactivation | 2.00с | once | state end 0.96с | играется на коллапсе безумия |

Blends/interrupt-safe точки — из HANDOFF таблицы (heart 1.08с, kick 1.60с,
mania 1.42с, embrace 1.62с, counter 0.50с, evangelium 3.00с/1.20с); прерывания
до authored event отменяют эффект без стоимости, после — эффект уже сработал.

Драйвер: клиентский `RegulusAnimationDriver` (state→clip, blends, restart-защита
— `PlayState.STOP` держит последний кадр); сервер шлёт одно событие
`RegulusAnimS2CPayload(clipId, startTick)` через `PlayerLookup.tracking` —
анимацию каста должны видеть и другие игроки. `var.regulus_<clip>_time` —
явный вход каждого клипа (по HANDOFF), драйвер его кормит.
Не-Regulus и не-EMF клиенты: fallback — без анимации, механика не зависит.

Локомоция: пак задаёт только клипы поверх плеер-модели — ходьба/бег остаются
ванильными. Правило драйвера: `каст-клип > idle-клип > ванильная локомоция`;
касты по дизайну останавливают/тормозят движение (slowness на кастах, ритуал
срывается движением), поэтому конфликт «бежит внутри позы» почти не виден.
Опция-запас: маскировать касты по верхнему телу (torso+arms+head), если в игре
будет заметно — решается на этапе реализации драйвера, не в спеке.
